# Source authorship and dependency notices

The mathematical source payload is reused from the pinned OpenAI project and the exact selected additive extension project. Upstream file headers, names, copyrights and proof bodies are preserved. The original OpenAI project's license is copied byte-for-byte as `lean/UPSTREAM-LICENSE` and also remains at `project/LICENSE` in the source archive. This document does not replace or broaden that license.

`DEPENDENCY-LICENSES.json` identifies every locked dependency by upstream URL and exact revision, and lists the license/notice entries actually included in the source archive. Existing dependency notices and copyright headers are preserved, including differently licensed notices such as Unicode data notices. Dependency code is not represented as newly authored by this release's maintainers.

Ten earlier local snapshots lacked a standalone license file: `belyi`, `formal-schemes`, `tempered-fundamental-groups`, `oka`, `orbicurve-cores`, `heights`, `genl`, `tate-curves-theta`, `gromov`, and `StrongPNT`. Inspection of the actual 12,205-module terminal closure showed zero modules from all ten. Their full source trees, metadata copies and license-less compatibility source snapshots are excluded from this public payload. Their precise upstream pins remain as fetched-only configuration dependencies; no license is assigned to those repositories. Every dependency whose actual proof sources are vendored has a preserved standalone license.

The 23 compatibility patch files are still needed by the unchanged Lake configuration. They are exact Git blobs under `lean/patches` in the pinned OpenAI commit. The verbatim upstream repository root license is included as `OPENAI-REPOSITORY-LICENSE`; `OPENAI-LICENSE-PATCH-PROVENANCE.json` records the byte-for-byte comparisons. The recipient recipe applies these exact retained patches inside freshly fetched, isolated dependency checkouts before restoring the loaded-source overlay. This avoids redistributing gratuitous unused package source copies while retaining the original build configuration and exact proof bytes. Repository-level license and new-extension attribution choices remain with the publication owner.

The compatibility patches in the source archive are exact reviewed build-compatibility files from the admitted project. They include substantive changes. Source provenance and revision data are retained separately from the mathematical admission: a pinned dependency, copied license or checksum is not itself a theorem proof.
